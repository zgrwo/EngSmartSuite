# ADR-0004: CSV 非 UTF-8 编码策略 —— 显式声明取代自动探测

**日期**: 2026-09-21
**状态**: 已确认

## 上下文

`ROADMAP.md` 决策门「非 UTF-8 编码探测（charset-normalizer/chardet）」的触发条件为
「出现繁体（Big5）来源的真实用户数据或误读报告」，状态长期为「未触发」。

2026-09-19 完成 E5 修复（移除 latin-1 兜底）后，CSV 自动回退链固定为
`utf-8-sig → utf-8 → gbk`，并留下一个已知缺口，由报警钉子测试钉住：
`tests/services/test_data_io.py` 中的
`test_big5_short_header_is_silently_misdecoded_as_gbk_known_gap`
——Big5 短表头被 GBK **静默误解码**（`批號` → `у腹`），用户会基于错误列名得到错误结论。

2026-09-21 对「引入编码探测依赖」做了可行性验证（charset-normalizer 3.5.1，
`cp_isolation=[gb18030, big5]`，真实中文语料 + 合成语料，样本按最后一个换行截断）：

| 样本字节 | GBK 判对 | GBK 误判为 Big5 | 无候选 | Big5 判对 |
|---|---|---|---|---|
| 0–63 | 47.8% | **51.5%** | 0.6% | 99.3% |
| 64–127 | 80.3% | 19.6% | 0.1% | 99.5% |
| 256–511 | 95.6% | 4.2% | 0.2% | 99.6% |
| ≥1024 | 99.4% | 0.5% | 0.2% | 99.5% |

附加实测：

- 库默认 `threshold=0.2` 时 `best()` 在真实 GBK 长样本（~2.5KB）上 **30% 返回 `None`**；
  放宽到 `threshold=1.0` 后降至 0.7%。
- 自研判别器否证：GB2312 常用字覆盖率实测不可分（Big5 正确文本 0.5 vs
  GBK 误读成 Big5 的 0.4~0.0，阈值重叠）。

**结论**：GBK 与 Big5 字节范围大面积重叠，二者在短样本上**不可可靠区分**。自动探测
达不到 100% 正确，采用它会给当前 100% 正确的 GBK 文件引入**新增的静默乱码通路**
（短样本最高 51.5%，≥1KB 仍有 0.5%），即用「一类静默错误」换「另一类静默错误」。

## 决策

**不引入编码自动探测依赖。** 非 UTF-8 编码按下述确定性规则处理：

1. **BOM 优先（确定性）**：读取文件头，命中 UTF-8 / UTF-16 / UTF-32 BOM 时直接使用
   该编码。BOM 是文件自描述，判定结果确定且无启发式。
2. **显式声明**：新增 `encoding` 参数（CLI `--encoding`、Web 上传面板「文件编码」下拉框），
   用户可为 CSV 显式指定 `utf-8-sig / gbk / gb18030 / big5 / utf-16`。
   显式指定时**只**按该编码解析，失败即中文报错。
3. **回退链保持不变**：未指定且无 BOM 时，仍按 `utf-8-sig → utf-8 → gbk` 依次尝试；
   全部失败抛 `CsvEncodingError`（安全失败，不猜）。
4. **明确不做**：
   - utf-16/utf-32 **不进入**自动回退链（无 BOM 的 GBK 文件可被 `utf-16` 静默解码成乱码，
     属于新增静默错误通路）；
   - 不引入 charset-normalizer / chardet / cchardet；
   - 不做基于内容的启发式编码判别。

## 原因

1. **确定性优于启发式**：显式声明的正确率是 100%；自动探测上限 99.4%，且失败方向是静默乱码。
2. **零回归**：UTF-8 / GBK 用户的行为与错误语义完全不变，当前唯一 P0 类风险不扩大。
3. **适配单机单用户定位**（ADR-0003）：用户知道自己的文件来自哪个系统，让知情方声明
   比让库去猜更便宜也更可靠。

## 约束

- `services/data_io.py` 中的 `read_csv_with_encoding` 是 Web 与 CLI 唯一的 CSV 读取入口，
  两条入口的编码策略、错误文案必须一致（差分测试守护）。
- 受支持编码白名单只在 `services/data_io.py` 定义一处（`SUPPORTED_CSV_ENCODINGS`）；
  Web 下拉框选项必须取自该白名单（一致性测试守护）。
- 未指定编码且无 BOM 时，禁止尝试 `utf-16` / `utf-32`。
- 禁止引入编码探测依赖（charset-normalizer / chardet / cchardet）。
- BOM 判定必须按「长 BOM 优先」顺序比较（UTF-32LE 的 BOM 前两字节与 UTF-16LE 相同）。

## 影响

- **正面**：UTF-16 / UTF-32 文件由「报错」变为「正确读取」；Big5 等编码可经显式声明正确解析；
  消除「猜测编码」这一失败模式。
- **代价**：未指定编码的 Big5 文件仍会被 GBK 静默误解码——报警钉子测试保留，
  由文档与错误提示引导用户改选编码。
- **需同步更新**：`ROADMAP.md`（决策门状态）、`docs/specification/api-reference.md`、
  `docs/user-manual/03-data-import.md`、`docs/user-manual/10-faq.md`。

## 演进

- **2026-09-21**: 建立本决策，替代 `ROADMAP.md`「非 UTF-8 编码探测」决策门的原定方向
  （由自动探测改为显式声明 + BOM 确定性判定）。
