# ADR-003: 部署形态 —— 单机/单用户本地工具

**日期**: 2026-09-21
**状态**: 已确认（决策门 D1）

## 上下文

2026-09-19 的外部评估报告（`logs/reports/EngSmartSuite_评估报告.pdf`）把四条问题列为 P0/P1：

| 编号 | 问题 | 报告严重度 |
|------|------|-----------|
| E1 | 用 Flask 开发服务器（`app.run`）对外提供服务 | P0 |
| E2 | 无认证授权，`--host 0.0.0.0` 后可任意访问 | P0 |
| E4 | 进程级全局状态（上传文件注册表），多 worker 下不共享 | P0 |
| E27 | 无 Docker/compose 部署产物 | P1 |

源码验证（`docs/superpowers/plans/2026-09-19-excellence-improvement-priority-plan.md` §2）确认现象属实，
但严重度排序与项目**实际定位**错位：上述四条只在「内网多用户部署」目标下才是 P0。

项目事实：单人维护、无第二贡献者、目标用户为国内制造业工艺工程师，安装路径为
`pip install` / 一键脚本后**在本机浏览器打开 `localhost:5050`**（README 与手册均为该用法）。
本 ADR 就是要把「部署形态」这一未经记录的隐含前提**显式化**，否则代码、文档与"生产就绪"声明持续错位。

## 决策

**选 A：维持单机/单用户本地工具定位，不做生产部署栈。**

具体含义：

1. `web/app.py` 保留 `app.run()`（Werkzeug 开发服务器）作为唯一内置运行方式，**不引入** waitress/gunicorn；
2. **不实现**应用层认证授权；安全边界由「仅监听 `127.0.0.1`」承担（这是 `main()` 的默认值与强制行为）；
3. E1/E2/E4/E27 降级为**条件项**，不进入排期；
4. README 与用户手册明确声明部署边界，并给出用户自行反代的最小示例（nginx / waitress 两行），
   把"对外暴露"的责任与选择交给用户；
5. `pyproject.toml` 的 `Development Status` 维持 `5 - Production/Stable`：稳定的是**分析引擎与
   单机使用路径**，不是"公网服务"（该分类器描述项目成熟度，不是部署拓扑承诺）。

## 原因

1. **成本与收益不对称**：承诺内网多用户需要同时做 D3（waitress）+ D4（鉴权）+ D2（消除全局状态，
   本 ADR 同期已完成），估算 1-2 周；而单人维护下这些组件一旦引入就是**持续运维面**
   （凭据轮换、worker 扩容、反向代理配置、容器镜像维护）。
2. **与既有事实一致**：代码、测试、文档、一键脚本全部按单机使用设计；无任何用户提出内网共享需求
   （计划 §8 开放问题 #6 的答案是"无"）。
3. **用户自行反代更划算**：需要内网共享的用户，在其既有运维体系里加一段 nginx + waitress 配置即可，
   不需要项目自养部署栈，也不需要项目承担鉴权设计。
4. **保留演进路径**：若未来出现真实的内网多用户需求，重开本 ADR 并**同时**实施 D3+D4+D2 即可；
   D2 已提前完成，且它同时让代码更简单（消除了"多 worker 下注册表不共享"的隐性假设）。

## 影响

- **正面**：省下 1-2 周；文档与代码的定位声明一致；`web/app.py` 的控制流保持扁平（无环境变量分支）。
- **负面（已接受的边界）**：
  - 用户若把 `--host 0.0.0.0` 直接暴露到网络，**没有任何应用层防护**（只有 CSP/CSRF，防的是跨站请求伪造，
    不是访问控制）。此风险由 README/手册的显式警告承担。
  - 单进程假设：多 worker 部署下**会话内数据路径**依赖 `session`（cookie）而非进程内注册表（D2 已消除），
    但 Flask `session` 的 secret 与临时目录需用户自行保证；本项目不对此提供支持承诺。
- **不产生**新的代码分支、配置项或依赖。

## 替代方案

| 方案 | 结论 | 理由 |
|------|------|------|
| B. 承诺内网多用户部署（D3+D4+D5） | ❌ 否决 | 单人维护下引入持续运维面；无真实需求；鉴权设计无安全评审资源 |
| C. 直接删除 Web UI，只保留 CLI | ❌ 否决 | Web UI 是 ADR-002 的核心决策与主要用户入口（列定义面板/图表交互是工程师生效路径） |
| D. 内置可选鉴权但默认关闭 | ❌ 否决 | "默认关闭的鉴权"给人虚假安全感，且需长期维护；边界声明 + 用户反代更诚实 |
